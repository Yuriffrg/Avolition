# Whitehound standalone FBX exporter

Implemented `owpreview/fbx.py` and `owpreview/export_pose.py`. The writer has no Blender or Autodesk SDK runtime dependency. It writes deterministic binary FBX 7400 with fixed creation metadata, sequential object IDs, compressed numeric arrays, model/mesh nodes, skin clusters and bind poses, original-FPS sampled animation curves, relative texture paths and portable Phong material connections.

## Compatibility decisions

- Mesh and LimbNode model properties explicitly set `DefaultAttributeIndex=0`, following Blender's `fbx_data_object_elements` and leaf-bone writer. The SDK default is invalid `-1`; an attached Geometry/NodeAttribute alone does not guarantee that `GetNodeAttribute()` resolves it. Omitting this caused the 0.6.0 Cinema 4D null-object failure. See Autodesk's [FbxNode reference](https://help.autodesk.com/cloudhelp/2020/ENU/FBX-API-Reference/cpp_ref/class_fbx_node.html).
- Actual keyed transforms use Blender's `A+` property flag. Curve nodes declare their parent compound `d` and X/Y/Z channels; animation layers explicitly carry Blender's template defaults. The selected animation is declared in the document and Takes list, with local/reference timing. These fields make node typing and animation discovery explicit without changing sampled transforms.

- Geometry vertices, local translations, animated translations, skin bind matrices and pose matrices are multiplied by 100. The file declares centimetres (`UnitScaleFactor=1`), with unchanged object/joint scale channels and no scaled wrapper. This matches the working Cinema 4D importer's `IMPORT_SCALE=100` even when an importer uses numeric scene values. Default Y-up and optional Z-up rotate only the source root transforms.
- `formats.build_export_hierarchy` retains the working entity importer's entity/model/skeleton wrappers, meshes under their model, child entities under the correct hardpoint joint, and bone parents. Model-group and scale-helper joints are no longer synthesized. Displayed joint names use the same `BoneUtil` table from io_scene_owm, translated by Jupit; internal raw IDs still match animation tracks. Duplicate displayed names on separate component rigs remain unchanged. Skeleton wrapper names come from the `.owmdl` filename; child entity names come from the original entity reference, without its `.003` suffix.
- Non-root bone nodes use native FBX `InheritType=2` (`Rrs`); model wrappers and root bones use `RSrs`. `Rrs` retains the parent's full transform for child position while excluding the immediate parent's local scale from child rotation/scale inheritance. It reproduces the game's non-inherited joint scale without adding helpers or changing joint paths. Autodesk's [transformation example](https://help.autodesk.com/cloudhelp/2017/ENU/FBX-Developer-Help/cpp_ref/_transformations_2main_8cxx-example.html) describes these inheritance modes. The SDK evaluator verifies both ordinary and nested rotated/scaled attachments against the source pose oracle.
- Animation samples include exactly source frames `0..lastFrame`, with times `round(frame / sourceFPS * 46186158000)`. Curves are linear; quaternion interpolation and root rest-basis translation follow `web/pose.js` and the actual Blender oracle. Export does not append an extra final sample. A one-million bone-frame limit bounds memory use; samples use preallocated NumPy arrays.
- Mesh vertices, triangle winding, normals, both UV layers, material slots, normalized weights and bind matrices are retained. Each skinned mesh remains under its original model. Its bind matrices and animated skeleton account for inherited attachment motion, avoiding doubled transforms.
- Blender 5.1's bundled FBX importer does not support `InheritType` and can fail to discover a separate armature nested beneath a bone (`link_hierarchy`, `mesh.armature_setup[self]`). The former exporter flattened the game hierarchy to work around this Blender limitation. The current exporter preserves the requested Cinema 4D hierarchy and uses FBX's native inheritance instead; such nested rigs may still need a different Blender FBX importer. Autodesk SDK validation is the authority for these files.
- Material texture slots match Blender's established FBX conventions. In particular, roughness maps connect to `ShininessExponent`, metallic maps to `ReflectionFactor`, alpha maps to `TransparencyFactor`, normals to `NormalMap`, and colored emission to `EmissiveColor`. Blender directly maps those texture inputs to corresponding Principled inputs, despite legacy property names. Other importers may interpret them differently. Secondary UV sets are written and named, but Blender's importer currently ignores the texture `UVSet` property; manual secondary-UV material assignment can be necessary. Unbaked emission masks and separate AO maps lacking a portable material slot are omitted with explicit warnings.

## Verification

- `tests/test_fbx.py`: 12 tests cover the source pose oracle, Euler continuity, deterministic bytes, options, unchanged duplicate names, centimetre vertices/translations/binds, friendly joint names, exact hierarchy connections, native inheritance, unbaked emission suppression, SDK-style default-attribute resolution and animation discovery.
- `fbx_fixture.py` generates original synthetic geometry, a rotated/translated root, nonuniform animated parent scale, missing channels, a weighted nested attached rig and both UV sets.
- `fbx_roundtrip.py` imports generated FBX through actual Blender 5.1.2 and records evaluated bones/mesh vertices/material links. `fbx_verify.py roundtrip-Y.json roundtrip-Z.json` passes102 comparisons; maximum observed error1.35003e-5 model units.
- `fbx_material_fixture.py` generates a synthetic textured entity with bakeable AO/emission. Actual import resolved13 sibling PNG maps across3 materials.26 checks covered texture existence, base/normal/roughness/metallic/alpha links and baked colored emission with strength2.
- Version 0.6.1 repeats the Blender checks under `fbx-qa-v061` (102 geometry/animation and 50 material comparisons). Independent ufbx checks pass 58 comparisons of geometry, weights, bones and deformed vertices, maximum error 2.42e-7.
- Actual Autodesk FBX SDK imports of old/fixed fixtures reproduce and resolve the null-attribute defect: old Y/Z files return no default mesh or skeleton attributes, while fixed files return two meshes and nine skeleton nodes. The actual packaged executable's textured FBX returns eight meshes, four skeleton nodes, three animated/moving nodes, 192 vertices and 96 polygons. All fixed attached attributes are active. Reports are under `fbx-qa-v061/autodesk-sdk-before-after.json`; the SDK is development-only and is not shipped.
- Version 0.7.0 independently checks 700 geometry/hierarchy/world-pose/skinned-vertex comparisons through Autodesk's FBX SDK across Y-up and Z-up, including nonuniform scaled parents and nested rotated component rigs; maximum error is 0.000048 centimetres. `fbx_v070_fixture.py` and `verify_fbx_v070_sdk.py` produce these reports under `fbx-qa-v070`.
- A real Gameplay1P entity with six meshes, 18,415 vertices and 105 joints was checked using a 50-frame, 93-track clip. All exported joint labels match labels in the user's correct Cinema 4D project; the SDK passed 768 comparisons including complete skinned meshes at five frames, with maximum error 0.0000063 centimetres. Native C4D payload preparation succeeded for all 19 available 93-track clips. These user-owned assets and their generated FBX tests are development-only and are not distributed.
- Actual Cinema 4D import/render testing remains unavailable: installed c4dpy processes exit before executing the validation code. Blender round-trip results above describe versions 0.6.0/0.6.1, not the newly preserved nested hierarchy.
